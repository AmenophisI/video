## 2. プロダクト概要

本アプリは、端末内に保存されている動画ファイルを自動的に検出し、動画専用のライブラリとして一覧表示・検索・整理・再生できるアプリである。

一般的な写真ギャラリーとは異なり、動画ファイルに特化したUIを提供し、動画のタイトル、保存フォルダ、撮影日時、再生時間、解像度、ファイルサイズ、HDR、スローモーション、360度動画などの属性をもとに、ユーザーが目的の動画をすばやく見つけられることを目的とする。

---

## 3. 開発目的

### 3.1 目的

* 端末内の動画を一元的に管理できるようにする。
* 動画だけを対象にしたシンプルで高速な一覧画面を提供する。
* フォルダ単位、動画単位の両方で動画を探せるようにする。
* 動画の検索、並び替え、共有、削除、移動、コピー、名前変更を可能にする。
* 簡易再生と全画面再生をスムーズに切り替えられるようにする。
* プライベートな動画を保護できる仕組みを提供する。

### 3.2 成功指標

| 指標          | 目標                                 |
| ----------- | ---------------------------------- |
| 初回ライブラリ表示速度 | 1,000件の動画で3秒以内に一覧表示を開始             |
| 2回目以降の起動速度  | 1,000件の動画で1.5秒以内に一覧表示              |
| 検索応答速度      | 1,000件の動画で入力後500ms以内に結果更新          |
| クラッシュ率      | 月間クラッシュフリー率99.5%以上                 |
| 権限許可後の動画検出率 | Androidのメディアストアに登録されている動画の95%以上を検出 |
| 主要操作完了率     | 再生、共有、削除、検索、並び替えの操作完了率95%以上        |

## 4. 前提条件

### 4.1 Androidストレージ仕様

本アプリは、Androidの共有ストレージ上にある動画ファイルを扱う。Androidでは、他アプリが作成したメディアファイルへアクセスする場合、MediaStore経由で対象メディアを取得する設計が推奨される。Android 10以降では、アプリ自身が作成したメディアについてはストレージ権限なしでアクセスできるが、他アプリが作成した動画へアクセスする場合は適切なメディアアクセス権限が必要となる。([Android Developers][1])

Android 13以降で動画ファイルにアクセスする場合は、従来の `READ_EXTERNAL_STORAGE` ではなく、動画用の `READ_MEDIA_VIDEO` 権限を使用する。Android 14以降では、ユーザーが一部の写真・動画だけをアプリに許可できる「Selected Photos Access」に対応する必要がある。([Android Developers][2])

### 4.2 サムネイル生成

動画サムネイルは、原則としてAndroid標準の `ContentResolver.loadThumbnail` または同等のAPIを利用して取得する。旧来の `MediaStore.Video.Thumbnails` はAPI 29で非推奨となっており、より制御しやすい `ContentResolver.loadThumbnail` への移行が推奨されている。([Android Developers][3])

### 4.3 商標・UIに関する前提

本アプリはSamsung Video Libraryと同等の機能性を参考にするが、Samsungの商標、アイコン、UI文言、画面デザイン、アプリ名を直接流用しない。

* DRM保護コンテンツの復号

## 15. ファイル操作仕様

## 15.1 削除

* 削除操作はユーザー明示操作でのみ実行する。
* 削除前に対象件数を表示する。
* OS標準の削除確認が必要な場合はシステムフローを利用する。
* 削除成功後、一覧、検索結果、フォルダ件数を更新する。
* 一部削除失敗時は成功件数と失敗件数を表示する。

## 15.2 移動

* 移動前に移動先フォルダを選択する。
* 移動中は進捗を表示する。
* 移動完了後、元フォルダと移動先フォルダの件数を更新する。
* 移動失敗時は元ファイルを保持する。
* 一括移動時はファイル単位で成功／失敗を記録する。

## 15.3 コピー

* コピー前にコピー先フォルダを選択する。
* コピー中は進捗を表示する。
* コピー先の空き容量を確認する。
* 同名ファイルがある場合の処理をユーザーに選択させる。
* コピー失敗時は不完全ファイルを削除または隔離する。

## 15.4 名前変更

* 拡張子は原則維持する。
* ファイル名として使用できない文字は入力時に検出する。
* 空文字、空白のみの名前は禁止する。
* 同名ファイルがある場合は保存不可とする。
* 名前変更完了後、一覧と詳細画面に即時反映する。

## 16. プライベート機能仕様

## 16.1 基本仕様

プライベート機能は、ユーザーが選択した動画を通常の一覧・検索結果から非表示にし、認証後のみ閲覧可能にする機能である。

## 16.2 認証方式

* 端末の生体認証
* 端末のPIN／パターン／パスワード
* アプリ独自PIN

## 16.3 プライベート化処理

* 対象動画をプライベート領域へ移動する。
* 通常一覧から対象動画を除外する。
* 検索インデックスから対象動画を除外する。
* サムネイルキャッシュも通常領域から削除する。
* プライベート解除時は指定フォルダへ戻す。

## 16.4 注意表示

プライベート化前に以下をユーザーへ表示する。

* アプリ削除時にプライベート動画へアクセスできなくなる可能性
* 端末のバックアップ対象外となる可能性
* プライベート解除により通常一覧へ再表示されること

## 17. サムネイル・キャッシュ仕様

## 17.1 サムネイル生成

* 一覧表示時に必要な分だけサムネイルを遅延生成する。
* 画面外の動画については優先度を下げる。
* サムネイル生成はメインスレッドで実行しない。
* 生成失敗時はデフォルトアイコンを表示する。

## 17.2 キャッシュ

* メモリキャッシュとディスクキャッシュを併用する。
* キャッシュ上限を設定画面で変更できるようにする。
* 元動画が削除または更新された場合、対応するキャッシュを無効化する。
* プライベート化された動画の通常キャッシュは削除する。
* キャッシュ削除機能を設定画面に提供する。

## 19. 通知・バックグラウンド処理

## 19.1 通知

初期リリースでは常駐通知を使用しない。

ただし、以下の長時間処理では必要に応じて進捗通知を検討する。

* 大量ファイルのコピー
* 大量ファイルの移動
* 大量ファイルの削除
* 初回インデックス再構築

## 19.2 バックグラウンド処理

* 大量ファイル操作はバックグラウンド処理として実行可能にする。
* OSにより処理が中断された場合、次回起動時に状態を復元またはロールバックする。
* バックグラウンド中に動画ライブラリ全体を頻繁にスキャンしない。
* バッテリー消費を抑えるため、差分更新を優先する。

## 27. リスクと対応方針

| リスク                 | 影響         | 対応                    |
| ------------------- | ---------- | --------------------- |
| Androidバージョンごとの権限差異 | 動画取得不可     | OS別に権限処理を分岐           |
| メーカー固有メタデータの差異      | タグ判定不可     | 判定不可の場合は非表示           |
| 大量動画で一覧が重い          | UX低下       | ページング、遅延読み込み、キャッシュ    |
| サムネイル生成負荷           | メモリ圧迫      | 非同期生成、サイズ制限、キャッシュ     |
| ファイル操作の失敗           | データ不整合     | トランザクション的処理、失敗時ロールバック |
| SDカード取り外し           | ファイルアクセス失敗 | 状態再確認、エラー表示           |
| プライベート領域の扱い         | データ消失リスク   | 事前警告、バックアップ方針明示       |
| DRM動画の再生不可          | ユーザー混乱     | DRMタグとエラー理由表示         |
| 外部編集アプリ依存           | 編集不可       | 対応アプリなしの案内表示          |
